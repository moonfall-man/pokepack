# Sprint Brief — Studio Pong (PONG), Sprint 2

- **Date:** 2026-08-13
- **Author:** Priya "PJ" Joshi, Senior Producer
- **Sprint:** PONG Sprint 2 — one dev, two tickets, built in order, each merge leaves the game runnable
- **Base:** Sprint 1 shipped complete — PONG-1/2/3, 11/11 points, zero open bugs. This sprint modifies `studio/projects/pong/` in place.

## Concept

Studio Pong grows from one fair fight into three: a difficulty select on the start/serve flow — Chill, Arcade, Ruthless — retunes the CPU's speed cap and the ball's speed ramp, with every tier still honestly beatable and the serve still never a cold ace. Pause on P and screen shake on scoring hits round out match feel, and the game still ships as double-click-from-disk static files with the ball the brightest object on screen.

## Design pillars

1. **Three honest fights.** Chill is a real game, not a tutorial that plays itself; Ruthless is a wall you can climb, not a cheat. The CPU speed cap stays below the ball's serve speed at every tier, and "beatable" stays a measured verdict per tier, not a vibe.
2. **Feel never lies about state.** Pause freezes the entire simulation and says so on screen; shake fires only when a point lands and never blurs what you need to read. Every effect still answers "what just happened?"
3. **Zero-friction to run.** Open `index.html` from disk, play. No install, no build, no network. Unchanged and non-negotiable.

## Ship constraint (non-negotiable)

Same as sprint 1: plain static files in the per-project folder `pong/` — `index.html`, `css/`, `js/` — plain script tags, no ES modules, no build step, no server code, and no audio. If a change breaks "double-click and play," it doesn't merge.

## This sprint ships

Two tickets, one dev, built sequentially; each ticket ends in a runnable state. Difficulty and screen shake enter scope here by studio-head directive — the front door the retro said they would have to use. If the sprint runs short, PONG-5 is the cut: PONG-4 alone still ships a complete upgrade.

### PONG-4 — Difficulty select: Chill / Arcade / Ruthless
Keyboard-driven difficulty select on the start/serve flow — offered before a match's first serve and again from the win screen — with the active tier visible on court. Three named profiles in the existing constants block, retuning exactly two knobs per tier: the CPU speed cap and the ball speed ramp. Arcade is sprint 1's shipped numbers (cap 300, ramp 24) untouched; Chill eases both; Ruthless raises both — but every tier keeps the CPU cap below the ball's serve speed, and the serve beat (center park, ~1s hold, shallow launch, no cold aces) is identical across tiers. **Done when:** all three tiers are selectable without a mouse, the choice reads in play, and sprint 1's beatability bar re-passes per tier — a mid-skill tester scores within 60 seconds on all three.

### PONG-5 — Pause and score shake
P toggles pause during play and during the serve beat: the whole simulation freezes — ball, paddles, speed ramp, serve countdown — behind a "PAUSED" overlay, and resume continues from the identical state. Screen shake on scoring hits only: a short, small, fast-decaying court offset when a point lands, never during a rally, built with the same layered-stroke discipline as sprint 1 (no shadowBlur). **Done when:** a dozen pause/resume toggles produce zero state drift, shake maps 1:1 to score events and never fires otherwise, and the measured-fps gate re-passes with shake firing and every sprint 1 effect on, from disk.

## Out of scope (do not build)

- Audio of any kind — SFX, music, mute toggles (studio-head directive: none this sprint)
- Two-player local, online play, or spectating
- Persistence of any kind — difficulty is chosen per session; no localStorage, nothing remembered
- Mid-match difficulty switching, adaptive/rubber-band AI, or CPU personalities — three fixed knob profiles only
- Pause *menus* — pause is a frozen state with one overlay, not a settings screen
- Any juice beyond sprint 1's trail/flash/pop plus the new score shake — no particles, no slow-mo, no flourish creep
- Touch/mobile controls, gamepad support, mouse-driven UI
- Frameworks, bundlers, TypeScript, asset pipelines — see ship constraint

If it isn't in a ticket above, it's a proposal for sprint 3, not a commitment in this one.
